# Backend Developer (Java, Python and API developer paths)

## Role guide

A backend developer builds the server side of an application: the logic, databases and APIs the app runs on. This covers data storage

## Skill roadmap

### 1. Prerequisites and foundations

- Core concepts: how the web works (HTTP, requests and responses, client and server), data structures and algorithms basics, how data

- Programming: one server-side language learned well. Python (Django, Flask, FastAPI), Java (Spring Boot) or JavaScript with Node.js

- Development environment: Git and GitHub, VS Code or an IDE such as IntelliJ, the command line, Postman or similar for testing APIs

- Switching from another field: testers, data analysts and frontend developers already know part of this. Start with one language and

### 2. Core and technical skill progression

- Level 1, fundamentals: language basics, a web framework, SQL (queries, joins, schema design), REST API design with routing, validat

- Level 2, core competencies: authentication and authorization (tokens), protection against injection and endpoint abuse, ORMs, testi

- Level 3, advanced: design for scale and reliability, microservices, message brokers such as Kafka, observability, handling producti

- Rough guide to experience: Level 1 matches 0 to 2 years of work, Level 2 about 2 to 5 years, Level 3 about 5 years and beyond.

### 3. Practical tooling and ecosystem

- Frameworks: Django, Flask or FastAPI; Spring Boot; Express.

- Databases: PostgreSQL or MySQL, MongoDB for NoSQL, Redis for caching.

- Cloud and DevOps: Docker, GitHub Actions or another CI service, a cloud platform (AWS, Azure or GCP), logging and monitoring tools

- API work: OpenAPI or Swagger documentation, rate limiting, API testing tools.

### 4. Hands-on projects and portfolio milestones

- Beginner: a notes or to-do API with a database, a URL shortener.

- Intermediate: a blog or learning management system with login, roles, tests and a live deployment, an e-commerce API with payments

- Advanced: a multi-service app with queues, caching and monitoring, deployed with containers and a CI pipeline, and a load-tested AP

Common mistakes: skipping databases, and collecting certificates instead of building working projects.
